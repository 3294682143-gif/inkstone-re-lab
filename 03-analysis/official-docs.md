## /docs/knowledgeBase/ai-chat

课题空间 课题AI对话 On this page 课题AI对话 课题 AI 对话是围绕当前课题展开研究交流的主入口。用户可以在这里直接提问，也可以引用知识库文件、选择思考深度和模型，让 AI 基于课题上下文持续推进分析、归纳和写作。 发起课题 AI 对话 ​ 进入课题后，中间区域会显示「基于课题」的对话入口。输入框支持直接提问，也支持通过 @ 引用知识库文件。输入区下方提供「快速」和「深度」两种思考模式，用户可以根据问题复杂度选择回答方式；右侧的模型选择入口默认显示 Auto，平台会自动选择合适模型。 当问题准备好后，点击发送按钮即可发起课题 AI 对话。课题 AI 对话会结合当前课题上下文、知识库文件和已添加工具，为用户提供更连续的研究支持。 引用知识库文件提问 ​ 对于需要基于文件回答的问题，建议在输入框中使用 @ 引用知识库文件。输入 @ 后，平台会展开当前课题知识库中的文件和文件夹，用户可以从中选择需要引用的文件，再继续输入具体问题。 这种方式适合让 AI 明确参考范围，避免回答停留在泛泛解释。常见用法包括：引用论文后总结核心贡献，引用多篇论文后比较方法差异，引用草稿后进行润色，或引用实验记录后归纳异常现象。 引用文件后，文件会以标签形式显示在输入框中。用户可以继续补充问题，例如「对比这两篇论文的核心方法」，再发送给 AI。平台会围绕被引用文件进行回答，帮助用户完成多文件对照阅读、证据整理和综述材料归纳。 历史对话记录 ​ 课题页右上角提供历史对话记录入口。点击后，页面右侧会展开「对话记录」面板，展示当前课题下的历史对话标题和时间。用户可以点击其中一条记录，回到之前的问题、结论和中间推理。 对于持续推进的研究任务，历史对话记录可以减少重复描述背景的成本。用户可以按问题阶段保留多轮对话，例如算法梳理、论文对比、综述草稿、实验方案讨论等，后续需要复盘时直接从记录中进入。 使用建议 ​ 课题 AI 对话适合用来推进问题，知识库适合存放文件。建议在提问时尽量说明目标，例如「基于这两篇论文整理研究空白」「把这些证据整理成综述提纲」「比较不同方法的优缺点」。问题越具体，越容易得到可沉淀、可复用的结果。

## /docs/knowledgeBase/create-project

课题空间 创建课题 On this page 创建课题 创建课题是使用课题空间的第一步。课题用于承载一个明确的研究方向，后续上传的文件、添加的工具、发起的对话和生成的内容都会围绕该课题组织。 打开创建入口 ​ 进入「课题空间」后，点击列表中的「创建课题」卡片即可打开创建弹窗。该入口适合在开始新的研究任务、整理新的论文文件或建立新的项目工作区时使用。 填写课题信息 ​ 在创建弹窗中，需要填写课题名称，并选择课题所属领域。课题名称建议使用具体研究对象或研究问题，例如「肿瘤靶点蛋白质的特异性抗体抗原结合 AI 预测」。领域用于帮助平台理解课题方向，当前支持通用、生命科学、地球科学、神经科学、材料科学、化学、物理、数学等类型。 课题描述为选填项，但建议补充研究目标、关键词、问题背景或计划使用的方法。描述越清晰，后续在课题对话和工具推荐中越容易形成稳定上下文。 创建后进入课题 ​ 点击「创建」后，平台会生成新的课题卡片。新课题会出现在课题空间列表中，用户可以从卡片进入课题工作区，继续上传文件、添加工具或发起对话。 已有课题卡片会展示文件数量和工具数量，便于用户快速判断该课题目前沉淀了多少内容。后续如果需要继续研究，直接点击对应课题卡片即可回到该课题。 使用建议 ​ 如果一个研究方向还处在探索阶段，可以先创建一个较宽泛的课题；当问题逐渐收敛后，再为具体子方向创建独立课题。对于长期研究，建议在课题描述中保留核心假设、关键词和预期产出，这样后续回到课题时更容易接上上下文。

## /docs/knowledgeBase/list

课题空间 知识库 On this page 知识库 知识库用于管理当前课题下的文件，是课题 AI 对话和后续产出的信息来源。用户可以在这里整理论文、文档、草稿和证据材料，并在对话时通过 @ 引用指定文件，让回答基于课题文件展开。 用户可以将将高价值论文、实验记录和阶段性输出及时沉淀到知识库中。知识库越完整，课题 AI 对话越容易围绕已有文件持续推进，而不是每次都从零开始补充背景。 查看课题文件 ​ 进入课题后，默认可在左侧资源区看到「知识库」页签。知识库中展示当前课题的文件和目录，例如参考论文、综述草稿、假设与证据等。用户可以通过目录结构把不同类型文件分开管理，避免文件长期堆积后难以查找。 页面顶部会持续显示当前课题信息，中间对话区则提示用户可以围绕本课题提问。知识库与对话区处在同一页面中，便于一边查看文件结构，一边发起问题。 新建目录与整理文件 ​ 知识库支持通过顶部的加号入口上传文件、上传文件夹或新建文件夹。用户可以按照研究流程建立目录，例如「参考论文」「实验记录」「数据说明」「假设与证据」「阶段性结论」等，再把相关文件归入对应位置。 当课题文件较多时，建议先建立文件夹再上传或保存文件。这样后续在对话中引用文件时，能够更快定位到相关内容，也便于团队成员理解当前课题文件的组织方式。 在具体文件夹上点击更多操作，可以继续上传文件、上传文件夹、新建子文件夹，也可以对当前文件夹进行重命名、移动或删除。该能力适合在研究推进过程中持续调整目录结构，例如把早期收集的论文移动到「参考论文」，把阶段性输出放入「综述草稿」。 打开文件与论文精读 ​ 在知识库中点击文件后，平台会在课题内打开文件预览。如果打开的是 PDF 文件，页面会展示 PDF 原文预览、页码、缩放等阅读控件，并提供「论文精读」入口。用户可以先在课题内快速查看文件内容，再跳转到论文精读进行更深入的结构化阅读、AI 对话和笔记整理。 该能力让课题空间中的论文文件可以直接进入精读流程，不需要用户重新上传或重新检索论文。 在对话中引用知识库 ​ 课题 AI 对话输入框支持通过 @ 引用知识库文件。用户可以在输入问题时输入 @ ，从弹出的文件列表中选择需要引用的文件，再提出具体问题。平台会围绕被引用文件进行回答，适合用于论文总结、证据对比、草稿润色、方法解释和结论提炼。 例如，用户可以引用一篇论文后提问「总结这篇论文的核心假设和证据链」，也可以同时引用多份文件，让 AI 对不同文献的结论进行比较。引用知识库文件能够让回答更贴近当前课题上下文。 引用文件后，文件会以标签形式出现在输入框中，用户可以继续补充具体问题并发送。截图中同时引用了两篇论文，并要求 AI 对比核心方法，适合用于多文件对照阅读和综述材料整理。 文件沉淀方式 ​ 课题空间中的文件来源可以来自用户上传，也可以来自论文检索、论文精读等论文工具模块中保存到课题的论文。 AI 对话中的高价值回复也可以沉淀为笔记。用户在 AI 回复下方点击「添加到课题」后，可以把该段回答保存到指定课题，形成可复用的知识库文件。该方式适合保存阶段性结论、证据整理、方法对比、综述段落等内容。

## /docs/knowledgeBase/overview

课题空间 概述 On this page 课题空间概述 课题空间用于把一个研究方向中的文件、工具、对话和过程产出组织在同一个工作区内。与一次性对话不同，课题空间更适合长期研究任务：用户可以先创建课题，再把论文、文档、实验记录和常用工具沉淀进去，后续围绕同一课题持续追问、归纳和产出。 进入课题空间 ​ 在平台左侧导航栏点击「课题空间」即可进入课题列表页。页面顶部展示课题空间标题和当前账号的空间用量，列表区域展示已有课题；如果需要开启新的研究方向，可以点击「创建课题」卡片新建课题。 已有课题会以卡片形式展示课题名称、课题描述、文件数量和工具数量。点击课题卡片即可进入该课题的专属工作区，继续管理文件、添加工具或展开课题对话。 课题工作区结构 ​ 进入某个课题后，页面顶部显示当前课题名称和描述，便于用户确认正在处理的研究对象。左侧为课题资源区，支持在「知识库」和「工具」之间切换；中间是围绕当前课题展开的 AI 对话区；右侧可打开「对话记录」，查看历史对话。 课题空间的核心逻辑是把文件、工具和 AI 对话连接起来。知识库提供课题文件来源，工具提供专业能力，对话区负责提问、追问和归纳，让研究上下文可以持续积累。 典型使用流程 ​ 一个完整的课题通常从创建开始。用户先填写课题名称、研究领域和课题描述，再进入课题工作区上传文件或整理目录。文件准备完成后，可以在对话区通过 @ 引用知识库文件，让 AI 基于指定文件回答问题。 当研究任务需要外部专业能力时，可以进入「工具」页签，为课题添加 SCP 或 Skills。添加后的工具会与当前课题绑定，后续对话可以结合课题文件和工具能力进行分析、检索、计算或生成。 使用建议 ​ 建议每个独立研究方向创建一个课题，避免把不同问题混在同一个空间中。课题名称应尽量表达研究对象，课题描述可以写清目标、关键词或方法边界，便于后续对话围绕同一上下文展开。 整理文件时，可按「参考论文」「实验记录」「综述草稿」「假设与证据」等目录归类。提问时优先引用相关文件，回答结果更容易回到课题文件本身，也便于后续沉淀到知识库中。

## /docs/knowledgeBase/tools

课题空间 课题工具 On this page 课题工具 课题工具用于为当前课题绑定可调用的专业能力。用户可以根据研究方向添加 SCP 或 Skills，让课题 AI 对话不仅能阅读文件，还能结合专业工具完成检索、计算、分析或特定任务处理。 查看已添加工具 ​ 在课题工作区左侧点击「工具」页签，即可查看当前课题已经添加的工具。工具区会区分 SCP 和 Skills，并显示各自数量。已添加的工具会在左侧列表中展示名称、领域标签和来源信息，方便用户确认当前课题已经具备哪些能力。 如果当前课题尚未添加工具，可以点击「推荐工具」进入工具选择弹窗。对于已经添加的工具，用户后续可以在课题 AI 对话中结合它们完成更具体的研究任务。 添加推荐工具 ​ 点击「推荐工具」后，平台会打开推荐工具弹窗。弹窗顶部显示当前课题名称，用户可以在 SCP 和 Skills 两类工具之间切换。每个工具卡片会展示工具名称、简介、领域标签、来源机构以及添加状态。 如果工具右上角显示加号，表示可以添加到当前课题；如果显示已添加状态，则说明该工具已经与当前课题绑定。用户可以根据课题目标选择合适工具，例如知识图谱查询、药物分子分析、蛋白质工程、文献检索或实验流程相关工具。 SCP 与 Skills 的使用场景 ​ SCP 更偏向可调用的专业服务或工具能力，例如数据库查询、模型服务、计算工具和实验流程工具。Skills 更偏向对某类任务的结构化处理能力，适合把常用分析方法、写作方式或流程化操作加入课题。 在实际使用时，不需要一次性添加所有工具。建议围绕当前课题最常用的任务添加少量高频工具，后续随着研究推进再补充。这样工具列表更清晰，对话时也更容易围绕相关能力展开。

## /docs/researchAssistant/deep

科研助手 深度研究 On this page 深度研究 深度研究对应对话框中的「深度」思考深度，面向复杂研究问题。科研助手会展示完整的思考过程、自动调用领域专家协作，并可生成结构化的报告文档。 深度思考与领域专家协作 ​ 在深度模式下，主 Agent（Intern InkStone Agent）会展示完整的分析与推理过程：先分析「需要做什么」、判断问题所属的学科方向，再按「工具路由规则」将任务委托给最合适的领域专家（SubAgent，如地球科学专家、物理专家等）。领域专家调用相应科研工具完成计算与分析后，主 Agent 整合结果，给出包含计算过程、结果汇总与科学解读的结构化解答。 生成报告文档 ​ 你可以让科研助手基于分析结果生成报告文档。系统会自动生成结构化的报告（标准 Markdown 格式，并附文档结构概览），文件保存到右侧「工作空间」。报告可直接在 Markdown 编辑器、Jupyter Notebook 或文档系统中渲染查看，也可转换为 PDF 或 Word 格式。 工作空间与预览 ​ 对话右侧的「工作空间」以文件树的形式收集本次对话产生的所有文件（如报告文档、代码等）。点击任意文件即可在线预览其内容，方便随时查看与下载。

科学工具 Skill 使用指南 On this page Skill 使用指南 一、这是什么 ​ Skill 是封装好的科研能力单元（如蛋白结构解析、分子对接等），以文件夹形式打包发布。使用方式很简单：在 Skill 广场挑选需要的 Skill，把它的文件夹下载到本地，再接入你自己的开发环境即可使用——平台侧不做在线编排或运行，Skill 本身就是一份可移植的能力包。 二、开始前的准备 ​ 已登录 Intern Discovery，进入「科学工具 → Skill」广场。 明确要下载的 Skill 名称（可按学科领域 / 用途筛选）。 已准备好接入的目标环境（如本地开发工具、智能体客户端等），并了解该环境读取外部 Skill 的方式。 三、下载 Skill ​ 打开 Skill 详情页，提供两种下载方式： 方式一：压缩包下载 ​ 在详情页点击「下载」，直接获取该 Skill 文件夹的压缩包（zip），解压后即为完整的 Skill 文件夹。 方式二：命令行下载 ​ 适合习惯终端操作、或需要在服务器 / 开发机上直接拉取的场景： # 使用 wget wget https://.../skills/{skill-name}.zip # 或使用 curl curl -O https://.../skills/{skill-name}.zip 具体下载地址以 Skill 详情页提供的链接为准。 下载完成后，解压得到 Skill 文件夹（ {skill-name} 替换成真实文件名）： unzip {skill-name}.zip 四、接入你的开发环境 ​ 将解压后的 Skill 文件夹放入你目标环境所要求的目录下（不同环境的目录规则不同，以目标环境的文档为准），即可在该环境中使用这个 Skill 提供的能力。 五、在课题空间中直接使用 ​ 除了下载到外部环境，你也可以直接在平台的「课题空间」中使用 Skill，让课题内的 AI agent 自动调用，全程无需下载和配置。 第 1 步：将 Skill 添加到课题 ​ 进入课题空间，点击「添加推荐工具」，在弹窗中切换到 Skills 标签（同一入口也可添加 SCP 工具），从系统推荐的工具中勾选需要的 Skill，添加到当前课题。 第 2 步：在 AI 对话中自动调用 ​ Skill 添加到课题后，在该课题的 AI 对话中，agent 会根据你的提问自动调用已添加的 Skill 与工具，返回结果，你无需手动指定或编写调用代码。 六、常见问题 ​ 问题 排查建议 下载的压缩包打不开 确认下载完整（未中断），可重新下载 wget / curl 命令报错 检查网络连通性，确认下载地址未过期 接入环境后未生效 确认 Skill 文件夹放置的目录符合目标环境要求，必要时重启该环境 想确认 Skill 内容 解压后查看文件夹内的说明文件（如 SKILL.md），了解该 Skill 的能力与使用方法

论文工具 引文核验 On this page 引文核验 引文核验是论文工具中的引用可信度检查功能，用于核对论文中的参考文献是否真实存在，以及正文观点是否被对应引文支持。该功能适合在论文写作、综述整理、投稿前检查和审稿辅助等场景中使用，帮助用户提前发现可能存在的错引、漏引或观点不匹配问题。 上传 PDF 核验 ​ 进入「论文工具 - 引文核验」页面后，用户可选择「文件上传」方式提交待核验论文。点击上传区域或「上传 PDF」按钮，即可上传单个 PDF 文件，文件大小不超过 100MB。上传后，用户可以选择核验模式，包括「验证引文与观点一致性」和「验证引文存在性」。 「验证引文与观点一致性」适合检查正文中对文献的表述是否符合原文内容；「验证引文存在性」适合检查参考文献条目是否真实可检索。 输入文本核验 ​ 除上传 PDF 外，用户也可以切换到「文本输入」方式，直接粘贴需要验证的正文段落和参考文献列表。输入框支持较长文本，页面会显示当前字数与上限。确认文本内容后，选择核验模式并点击「开始核验」，平台会根据输入内容提取引文并生成核验结果。 文本输入适合处理论文片段、草稿内容、引用段落或从其他文档中复制出的参考文献列表。当用户不方便上传完整 PDF 时，可以使用该方式快速检查局部引用质量。 查看核验结果 ​ 核验完成后，平台会进入核验结果页面。页面顶部展示全部、正确、存疑、未核验等统计数量，用户可以按状态筛选结果，快速定位需要人工复核的引用。 结果列表会逐条展示正文观点、参考文献信息、摘要证据、模型判断和来源链接。用户可以查看每条引用被判定为正确、存疑或未核验的原因，并通过链接进一步访问原始文献进行人工确认。 仅看引文 ​ 在结果页面中，用户可以开启右上角的「仅看引文」开关，将注意力集中到参考文献条目本身。开启后，右侧结果区会按条目展示引文内容、存在性判断和可访问链接，左侧 PDF 中对应的引用位置也会被高亮，方便用户在原文和核验结果之间对照检查。 该视图适合用于检查参考文献是否存在、链接是否可访问，以及文献条目是否需要补充或修正。 核验结果由模型基于可检索信息和摘要内容自动判断，可能存在误差。对于核心论证、争议性结论或投稿前最终版本，建议用户结合原文继续人工复核。

## /docs/thesisSpace/overview

论文工具 概述 论文工具概述 论文工具是科学发现平台面向科研文献工作的综合工具区，覆盖「论文检索」「论文精读」「引文核验」三类核心能力，帮助用户完成从发现论文、理解论文到检查引用可信度的完整流程。 论文检索支持用户用自然语言描述研究主题或搜索需求，并结合快速搜索、深度搜索与学科领域筛选，快速发现相关论文和高热论文。用户既可以围绕明确关键词检索，也可以输入较长的研究问题，让平台辅助扩展文献线索。 论文精读面向单篇论文的深度阅读场景。用户可上传 PDF，或从课题空间选择已有文献进入阅读流程，由 AI 辅助完成摘要提炼、重点理解和围绕全文的追问分析，适合快速把握论文内容和深入拆解研究方法。 引文核验用于检查论文正文中的引用是否真实存在，以及引用内容是否支撑对应观点。用户可上传 PDF，也可直接粘贴包含正文和参考文献的文本，平台会自动生成核验结果，帮助用户在写作、投稿或审稿前降低错引、误引风险。 通过这三类能力，论文工具把文献检索、阅读理解与引用检查连接在同一个工作流中，使科研用户能够更高效地完成文献调研与论文写作准备。

论文工具 论文精读 On this page 论文精读 论文精读是论文工具提供的 AI 辅助阅读工作台，面向单篇论文的预览、理解、追问、思维导图和笔记沉淀。用户可以上传本地 PDF，也可以从课题空间选择已有文献，进入阅读器后在同一页面完成原文阅读与 AI 辅助分析。 上传论文 ​ 进入「论文工具 - 论文精读」页面后，用户可以将 PDF 拖入上传区域，或点击「上传 PDF」选择本地文件。当前入口支持单个 PDF 文件，文件大小不超过 50MB。上传后，平台会解析论文内容，并进入论文精读页面。 如果论文已经保存在课题空间中，用户也可以点击「从课题选择」，直接复用课题内已有资料，无需重复上传。页面下方的「最近精读」会展示最近打开过的论文，方便继续之前的阅读任务。 精读页面布局 ​ 进入一篇论文的精读页面后，页面左侧为论文预览区，右侧为 AI 辅助区。左侧默认展示 PDF 原文，顶部提供页码切换、缩放比例调整，以及「PDF 原文」和「Markdown」两种预览方式。右侧提供「AI 对话」「思维导图」「笔记」三个功能页签，用于完成论文理解、结构化梳理和阅读过程沉淀。 页面右上角还提供「新阅读」和「添加到课题」入口。用户可以通过「新阅读」重新发起另一篇论文精读，也可以将当前论文保存到课题空间，方便后续在课题内继续管理和使用。 Markdown 预览 ​ 除了 PDF 原文外，论文精读还支持切换到「Markdown」预览视图。该视图会将论文内容按照自然语言阅读顺序重新排版，适合处理多栏排版、图文混排或阅读顺序复杂的论文。 在 Markdown 视图中，原本分栏的段落、公式和图片说明会被整理成更接近连续文本的阅读方式，帮助用户更顺畅地理解论文内容。对于移动阅读、复制引用片段或结合 AI 对话追问，Markdown 预览通常比原始 PDF 更易读。 结构化摘要 ​ 发起一篇论文精读后，平台会自动在「AI 对话」中生成结构化摘要。摘要通常围绕研究目标、核心方法、主要结论、创新点等维度展开，帮助用户在阅读正文前先把握论文的整体框架。 结构化摘要适合用于快速判断论文是否值得深入阅读，也适合在多篇论文调研时先建立初步理解。用户可以继续在下方输入框中追问，例如询问方法细节、实验设计、结论可靠性或与其他论文的差异。 AI 对话与保存笔记 ​ 在「AI 对话」页签中，用户可以围绕当前论文自由提问。AI 会结合论文全文回答问题，适合解释术语、总结章节、翻译段落、比较方法或提炼研究贡献。 对于 AI 回复，页面下方提供复制、重新生成、点赞、点踩等反馈操作。用户也可以将有价值的 AI 回复保存为笔记，保存后会在回复区域显示「已存为笔记」，并可在「笔记」页签中继续查看和管理。 思维导图 ​ 切换到「思维导图」页签后，平台会基于论文内容生成可视化结构。思维导图以节点形式呈现论文中的关键问题、方法路径、结论和延伸问题，帮助用户从局部段落阅读上升到整体逻辑理解。 用户可以在思维导图中缩放、查看节点详情，也可以对某个节点继续追问。该功能适合用于梳理论文结构、准备组会汇报、整理综述提纲，或快速发现论文中值得深入追问的知识点。 笔记 ​ 「笔记」页签用于集中管理阅读过程中沉淀的内容。用户可以点击「新建笔记」手动记录，也可以把 AI 对话中的回复保存为笔记。笔记会保留来源类型和生成时间，方便后续回看。 当用户在阅读过程中不断追问、翻译、总结时，可以把关键结论、重要解释和阶段性理解保存为笔记，形成属于当前论文的阅读记录。 划词操作 ​ 在 PDF 原文预览中，用户可以直接选中论文中的文字。划词后，页面会弹出快捷操作菜单，支持「笔记」「翻译」「问 AI」「复制」等操作。 该能力适合处理阅读过程中的局部问题。例如遇到不熟悉的术语，可以直接划词翻译；遇到难懂段落，可以选择「问 AI」让系统结合上下文解释；遇到关键表述，可以直接保存为笔记。

## /docs/thesisSpace/search

论文工具 论文检索 On this page 论文检索 论文检索是论文工具中的文献发现入口，支持用户用自然语言输入研究主题、论文线索或搜索要求，并结合搜索深度和领域筛选快速定位相关论文。该功能适合用于选题调研、查找最新进展、补充参考文献和寻找可深入阅读的核心论文。 输入检索需求 ​ 进入「论文工具」页面后，默认展示「论文检索」页签。用户可在输入框中输入研究主题或搜索要求，例如「大语言模型在科学发现中的应用综述」。输入内容可以是关键词、论文标题、研究问题，也可以是一段更完整的检索描述。 页面提供「快速搜索」和「深度搜索」两种模式。快速搜索适合快速获得候选论文，深度搜索适合更复杂、更全面的文献调研任务。输入完成后，点击「开始检索」即可提交任务。 查看检索结果 ​ 提交检索后，平台会进入论文结果页。页面顶部保留本次检索词，左侧显示返回入口，中间展示搜索结果列表，并在结果区上方显示命中的论文数量。每篇论文以卡片形式呈现，包含标题、作者、来源、年份、引用情况、论文类型、摘要片段、主题标签以及是否支持免费 PDF。 在结果列表中，用户可以直接浏览摘要片段判断相关性，也可以点击「展开全文」查看更完整的摘要内容。每篇论文右侧提供快捷操作，支持「添加到课题」和「精读」，让用户在检索阶段就能快速把候选论文沉淀到后续研究流程中。 筛选与排序结果 ​ 当检索结果较多时，用户可以在结果页上方继续筛选。当前结果页支持按年份、学科、类型和是否免费 PDF 进行筛选，也可以点击「清空筛选」恢复默认条件。右侧的「综合排序」用于调整结果排序方式，帮助用户从不同维度查看论文。 例如，用户可以先勾选「免费 PDF」快速找到可直接获取全文的论文，也可以通过年份筛选最新论文，通过学科筛选缩小研究范围。筛选条件会作用于当前检索结果，便于在同一主题下逐步收敛候选文献。 查看论文详情 ​ 在检索结果中点击论文标题或论文卡片，可进入论文详情页。详情页展示论文标题、作者、来源、发布时间、DOI、标签、免费 PDF 状态和摘要内容，用户可以在进入精读前先判断论文质量和相关性。 详情页右上角提供多个后续操作入口，包括「获取 PDF」「添加到课题」「引用格式」和「论文精读」。如果用户只想快速确认论文信息，可在详情页查看摘要和基础元数据；如果确认该论文有价值，可以继续保存到课题空间或进入论文精读。 保存论文到课题空间 ​ 检索结果页支持将论文直接加入课题空间。用户可以在单篇论文卡片右侧点击「添加到课题」，选择目标课题和保存位置后，点击「添加」即可把该论文沉淀到对应课题中，作为后续阅读、问答和研究整理的资料。 该能力适合在检索过程中快速收集候选文献。用户不必先进入详情页，也不必手动下载再上传，检索到有价值的论文后即可直接加入课题空间。 批量保存论文 ​ 当用户需要一次性整理多篇候选论文时，可以在结果列表左侧勾选多篇论文。勾选后，页面底部会出现批量操作栏，显示已选择的论文数量，并提供「添加到课题」和取消勾选等操作。 点击批量操作栏中的「添加到课题」后，平台会将所选论文一起加入指定课题。该功能适合做综述调研、课题资料初始化或批量收集候选文献时使用。 进入论文精读 ​ 无论是在检索结果列表还是论文详情页，用户都可以点击「精读」或「论文精读」进入精读流程。进入后，平台会围绕该论文提供 AI 辅助阅读能力，帮助用户继续理解论文摘要、方法、结论和细节问题。 因此，论文检索不仅用于查找文献，也可以作为后续论文精读和课题资料沉淀的起点。用户可以先通过筛选和摘要片段缩小候选范围，再把重点论文保存到课题空间或直接进入精读。 浏览高热论文 ​ 在检索入口下方，平台展示「高热论文」区域。用户无需输入关键词，也可以直接浏览当前热门论文，把它作为了解领域动态或发现研究选题的入口。 高热论文支持按领域切换，包括全部领域、生命科学、地球科学、神经科学、材料科学、化学、物理、数学等。点击某个领域后，页面会展示该方向下的热门论文卡片，卡片中包含论文标题、作者、来源年份、摘要片段和主题标签，便于用户快速判断论文是否值得进一步查看。 选择检索范围 ​ 当用户对研究方向较明确时，可先选择对应领域，再进行检索或浏览高热论文。领域筛选能够缩小文献范围，减少无关结果，尤其适合跨学科关键词容易产生歧义的场景。 如果初次检索结果过宽，建议在输入框中补充研究对象、方法、年份、任务类型或应用场景；如果结果过窄，可减少限制条件，改用更上位的研究主题重新检索。 使用建议 ​ 进行综述调研时，可以在检索需求中明确加入「综述」「survey」「review」「最新进展」等词；查找具体方法时，可以直接输入方法名、任务名或论文标题片段。对于不熟悉的领域，建议先浏览高热论文，再选择其中相关论文进入精读流程。

使用自定义镜像 ​ 镜像构建成功后，可在创建开发机或训练任务时选择【我的镜像】，再从列表中选择目标镜像。 如果在【我的镜像】中找不到已创建的镜像，请检查： · 镜像是否已构建成功。 · 创建镜像时选择的使用场景是否与当前开发机或训练任务一致。 · 当前选择的资源类型是否与镜像的基础环境兼容。 常见问题 ​ 为什么切换资源配置后，基础镜像列表发生变化？ 平台会根据 CPU、GPU 或 NPU 资源类型筛选兼容的基础镜像。切换资源配置后，请重新选择与目标硬件匹配的基础镜像。 快捷安装应该选择 apt 还是 pip？ 系统级软件包选择 apt，Python 软件包选择 pip。如两种依赖都需要，可点击【添加依赖】分别配置 apt 和 pip。 镜像构建失败后如何排查？ 点击【查看日志】，优先查看日志末尾的错误信息。重点检查软件包名称和版本是否存在、依赖之间是否冲突、基础镜像是否匹配资源配置，以及 Dockerfile 语法和路径是否正确。修正配置后，重新创建镜像。 为什么构建成功的镜像无法在开发机或训练任务中选择？ 请确认镜像的使用场景与当前功能一致，并检查所选资源是否与镜像环境兼容。开发机镜像不会出现在训练任务的镜像列表中，训练任务镜像也不会出现在开发机的镜像列表中。 删除镜像会影响正在运行的任务吗？ 不会。当前正在运行的开发机和训练任务不受影响，但后续将无法再选择和使用已删除的镜像。 达到镜像数量上限后怎么办？ 平台最多可创建 5 个镜像。可删除不再使用的镜像以释放配额；删除操作无法恢复，请先确认镜像后续不再需要。

科学计算 概述 科学计算概述 科学计算是科学发现平台为科研人员提供的一站式机器学习与开发平台，涵盖开发机与云盘两大能力，实现从环境准备到科研开发的全流程托管，帮助用户在云端高效开展项目开发与文件管理。 科学计算包含两大模块，开发机与云盘： 开发机支持快速创建、启动、停止和续时长的云端开发环境，按需获取 GPU / CPU 算力，并可挂载数据集、直接进入 VSCode 或 JupyterLab 进行项目开发，实现从环境配置到代码执行的全流程云端化。 云盘提供个人文件的统一管理，支持上传、新建、移动、复制、预览、下载和删除等常规文件操作；云盘会挂载到开发机的 /data 目录作为持久化存储，文件可直接在开发机编辑器中打开使用，实现文件与计算环境的无缝协同。 科学计算旨在为科研人员提供一体化的云端开发与文件管理体验，提升科研开发效率，让研究者专注于科研本身。

科学计算 推理服务 On this page 推理服务 推理服务列表 ​ 推理服务 用于将训练完成的模型部署为可在线调用的 API 服务，位于「科学计算 - 推理服务」标签页下。创建服务时，需要选择模型格式、模型来源、资源配置和运行环境，并填写请求、响应示例及运行时长。服务运行后，可在详情页查看调用地址、调用凭证和调用统计，也可通过在线调试验证服务响应。 界面说明 ：页面右上角提供服务名称搜索与【新建服务】入口；页面上方显示总算力点、已用算力点和资源使用情况。服务区分为【我创建的】和【分享给我的】两个标签页，支持按状态筛选，并可按创建时间或调用量排序。每张服务卡片展示服务名称、状态、服务 ID、描述、创建时间和调用量，并提供启动、停止、分享和查看等操作。 推理服务常见状态包括： · 排队中 ：服务已提交，正在等待资源调度或启动。 · 运行中 ，不要填写某个模型文件的具体路径。提交前请确认文件夹中包含所选模型格式运行时需要的完整文件，并保持模型目录结构不变。 本地上传 ​ 选择【本地上传】后，将压缩包拖拽到上传区域，或点击上传区域选择文件。支持 zip、tar、tar.gz 格式，单个文件大小不超过 500 MB。 资源配置决定服务运行时使用的计算资源，也会影响可选的运行环境、算力点单价和服务启动速度。请根据模型大小、推理框架和预计请求量选择合适的规格。 选择运行环境 ​ 在【运行环境】下拉列表中选择具体镜像。平台会根据模型格式和资源配置筛选兼容的运行环境。例如，Hugging Face 文本生成模型可显示 kserve-huggingfaceserver ，LightGBM 模型可显示 kserve-lgbserver ；实际选项以页面显示为准。 切换模型格式或资源配置后，运行环境的可选范围可能发生变化。请重新检查并选择与模型兼容的环境。 填写请求与响应示例 ​ 在【输入输出说明】中填写【请求示例（JSON）】和【响应示例（JSON）】，每项最多 500 个字符。选择模型格式后，系统会自动填入对应格式的示例，可根据模型的实际输入输出结构进行修改。 请求与响应示例用于说明服务的调用方式，并会显示在服务详情页。示例必须为合法 JSON，字段名称、数据类型和层级结构应与模型实际接收和返回的内容一致。 以文本生成模型为例，请求示例可包含模型名称和消息列表： { "model" : "internlm-chat" , "messages" : [ { "role" : "user" , "content" : "请介绍一下上海人工智能实验室。" } ] } 以上内容仅用于说明 JSON 填写格式。请以当前模型运行环境支持的字段为准，不要直接将不匹配的示例用于其他模型格式。 设置运行时长并创建服务 ​ 分别填写服务运行的小时数和分钟数，单次最长可设置为 7 × 24 小时。页面底部会根据所选资源和运行时长实时显示预计消耗的算力点、点数单价及当前剩余算力点。 'https://discovery-dev.intern-ai.org.cn/api/ml/v1/inference/user/call_api' \ -H 'Content-Type: application/json' \ -d '{ "call_api_path": "/inference/&lt;service_id>/", "call_api_credential": "&lt;call_api_credential>", "payload": "{\"inputs\":\"Replace with your model input\"}" }' 调用时请替换以下内容： · &lt;service_id> ：服务详情页显示的服务 ID。 · &lt;call_api_credential> ：服务详情页显示的调用凭证。 · payload ：传递给模型的实际请求内容。该字段为 JSON 字符串，需要对内部双引号进行转义，并与创建服务时填写的请求示例保持一致。 不同模型格式的请求结构可能不同。请优先复制服务详情页提供的调用信息和请求示例，不要直接复用其他服务的服务 ID、调用凭证或 payload 。 在线调试 ​ 具备调用权限时，可在服务详情页的在线调试区域输入请求内容，并点击【发送测试调用】验证服务响应。 服务停止后无法继续接收推理请求。如需再次使用，请重新启动服务并等待状态变为【运行中】。 续时长 ​ 运行中的服务可在操作菜单中点击【续时长】。分别填写需要增加的小时数和分钟数，确认续时后的运行时长、预计消耗、点数单价和剩余算力点后点击【确认】。 单次续时最长可设置为 7 × 24 小时。为避免服务到期停止，建议在当前运行时长结束前完成续时。 重命名服务 ​ 在服务操作菜单中点击【重命名】，输入新的服务名称后点击【确认】。服务名称最多 60 个字符。 重命名只会修改列表和详情页中显示的名称，不会修改服务 ID。调用服务时仍应使用详情页当前显示的服务 ID、调用路径和调用凭证。 分享服务 ​ 在【我创建的】服务卡片中点击【分享】，打开【分享管理】。可通过 SSO 昵称、ID、手机号或邮箱搜索用户，选择权限后确认分享。 平台支持以下分享权限： · 只读 ：可查看服务基本信息，但不能调用服务。 · 可调用 ：可查看服务信息并调用服务接口，也可使用在线调试。 分享管理窗口会显示已分享用户、权限、分享时间和状态，并支持调整或移除分享。被分享用户调用服务时，会使用服务所有者的运行资源，请谨慎授予调用权限。 调用凭证属于敏感信息。即使已经授予调用权限，也不建议通过聊天、邮件或公开文档额外传递明文凭证。 查看“分享给我的”服务 ​ 切换到【分享给我的】标签页，可查看其他用户分享的推理服务。服务卡片会显示分享者、我的权限、分享时间和服务创建时间等信息。 点击【查看】可打开服务详情。具备【可调用】权限时，可按详情页提供的调用信息调用服务；仅具备【只读】权限时，只能查看相应信息。 移除分享 ​ 在【分享给我的】服务卡片中点击【移除分享】，并在确认弹窗中点击【确认】。移除后，该服务将从【分享给我的】列表中消失，且无法再通过原分享关系查看或调用。 移除分享不会删除服务所有者创建的服务。如需再次访问，需要由服务所有者重新分享。 删除推理服务 ​ 删除操作仅适用于已停止的服务。在服务操作菜单中点击【删除】，页面会弹出二次确认；确认后，服务记录将被永久删除，且无法恢复。 删除前请确认服务已不再使用，并妥善保存仍需保留的模型文件、请求与响应示例、调用统计或日志信息。删除服务不会删除云盘中的源模型文件。 常见问题 ​ 服务一直处于排队中怎么办？ 服务排队通常与资源调度有关。可等待资源释放，并检查当前资源配额和算力点是否充足。如果长时间未进入运行状态，可停止服务后调整资源规格或运行时长，再重新启动或创建服务。 为什么没有可选的资源配置或运行环境？ 可选项会根据模型格式、账号配额和当前平台资源进行筛选。请确认模型格式已选择、账号有可用资源配额，并尝试重新选择模型格式或资源规格。切换资源后，请重新选择运行环境。 服务启动失败后如何排查？ 打开【日志】，优先查看末尾的错误信息。重点检查模型目录和文件是否完整、模型格式是否正确、模型是否与运行环境兼容，以及上传文件是否符合页面要求。 调用服务返回错误怎么办？ 请确认服务状态为【运行中】，请求地址、服务 ID 和调用凭证来自同一个服务，并检查 payload 是否为正确转义的 JSON 字符串。请求内容还需要与详情页中的请求示例及模型实际输入结构保持一致。 为什么在线调试按钮不可用或不可见？ 请先确认服务处于【运行中】状态，并检查当前权限。服务所有者或具备【可调用】权限的用户可以调用服务；仅具备【只读】权限时，不能使用在线调试。 服务到达运行时长后会怎样？ 服务到期后会停止运行，停止期间无法接收推理请求。如需继续使用，可在到期前执行【续时长】，或在停止后重新启动服务。 分享服务后，调用会消耗谁的资源？ 被分享用户的调用会使用服务所有者的运行资源。建议仅向确有需要的用户授予【可调用】权限，并定期在分享管理中检查已分享用户和权限。 停止服务后还能重新启动吗？ 可以。在已停止服务的卡片中点击【启动】，设置新的运行时长并确认。服务重新进入【运行中】状态后即可调用。 删除服务后还能恢复吗？ 不能。删除操作永久生效。删除前请确认服务记录、调用信息、日志及统计数据不再需要；云盘中的源模型文件不会随服务一起删除。

科学计算 训练任务 On this page 训练任务 查看训练任务列表 ​ 训练任务 是平台统一的模型训练与批量计算入口，用于将代码、镜像、数据集和计算资源组合为可托管运行的任务，位于「科学计算 - 训练任务」标签页下。任务创建后由平台自动调度运行，可在页面查看任务状态、资源配置、运行时长、算力点消耗、训练日志及迭代曲线。 训练任务支持 Git 仓库、本地上传和我的云盘三种代码来源，可选择 CPU、GPU 或 NPU 资源，并挂载训练数据集、验证数据集及自定义超参数。 云盘会挂载到训练任务的 /data 目录 ，如需持久化训练结果或中间产物，请将文件保存到 /data 目录，任务结束或资源释放后仍可保留。 界面说明 ：页面上方显示总算力点与已用算力点，如需补充算力点可点击【申请增配额】；右上角提供任务名称搜索与【训练任务】新建入口。任务区显示任务总数，支持按状态筛选及按创建时间排序。每张任务卡片展示任务名称、状态、任务 ID、资源配置、运行状态 / 时长、点数单价和已消耗算力点；将鼠标移至任务卡片上，可通过右上角操作入口查看日志、详情、重命名、重新训练或删除任务。运行中的任务还支持停止运行。 申请算力点 ​ 点击【申请增配额】，选择所需算力点档位（5000 点、10000 点或 20000 点），填写申请说明后点击【确认】即可提交申请。 新建训练任务 ​ 点击右上角【训练任务】进入新建自定义训练任务页面，依次完成任务信息、代码来源、启动命令、资源配置、镜像、数据集、超参数和运行时长配置后，点击【立即创建】即可提交任务。 阅读使用提示 ​ 创建任务前，建议先阅读页面顶部的使用提示，确认 TensorBoard 日志和云盘持久化目录的使用方式。 TensorBoard 日志 ​ 平台已集成 TensorBoard。如需在任务详情页查看训练曲线，请将 TensorBoard 日志保存到环境变量 TENSORBOARD_LOGDIR 指定的目录。 Python 示例： import os from torch . utils . tensorboard import SummaryWriter log_dir = os . environ . get ( "TENSORBOARD_LOGDIR" ) writer = SummaryWriter ( log_dir = log_dir ) 云盘持久化 ​ 云盘会挂载在 /data 目录下，作为训练任务的持久化存储空间。如需长期保存训练结果或中间产物，请将文件保存至 /data 目录下。任务结束或资源释放后，该目录下的文件仍可保留。 填写任务信息 ​ 填写任务名称和任务描述。任务名称为必填项，最多 60 个字符；任务描述为选填项，最多 200 个字符。 选择代码来源 ​ 平台支持以下三种代码来源： Git 仓库 本地上传 我的云盘 不同代码来源对应的默认工作目录不同。填写启动命令时，需要根据实际来源使用正确的运行时路径。 Git 仓库 ​ 选择【Git 仓库】作为代码来源时，填写 Git 仓库地址和分支名称，默认分支为 main 。平台会拉取指定分支的代码，并将代码复制到训练任务的临时工作目录 /code/workspace 下。 因此，填写【启动命令】时，需要基于 /code/workspace 填写要执行的脚本路径。例如，Git 仓库中的训练脚本路径为： LlamaFactory/platform/run_train.sh 则【启动命令】可填写： bash /code/workspace/LlamaFactory/platform/run_train.sh 请注意 ： /code/workspace 是训练任务运行时的临时代码目录，仅用于存放本次任务拉取的 Git 代码。需要长期保存的训练结果、模型文件和中间产物，请写入 /data 目录。 本地上传 ​ 选择【本地上传】作为代码来源时，将代码压缩包拖拽到上传区域，或点击【点击上传】选择文件。支持 zip、tar、tar.gz 格式，文件大小不超过 500 MB，禁止在代码包中包含模型权重与大数据集。平台会将上传的代码解压到训练任务的临时工作目录 /code/workspace 下。 填写【启动命令】时，需要基于 /code/workspace 填写要执行的脚本路径。例如，上传的代码中包含以下训练脚本： LlamaFactory/platform/run_train.sh 则【启动命令】可填写： bash /code/workspace/LlamaFactory/platform/run_train.sh 请注意 ： /code/workspace 仅用于存放本次任务上传并解压后的代码。需要长期保存的训练结果、模型文件和中间产物，请写入 /data 目录。 我的云盘 ​ 选择【我的云盘】作为代码来源时，需要填写代码所在的 文件夹路径 。请先在平台云盘中复制目标文件夹的路径，再粘贴到【云盘路径】输入框。云盘会挂载到训练任务的 /data 目录，启动命令中的路径需要以 /data 开头。 这里应填写代码文件夹的路径，而不是具体代码文件的路径。请勿填写 .py 、 .sh 、 .ipynb 等文件的地址。 示例一：代码位于指定文件夹 如果代码文件直接存放在云盘根目录下，则【云盘路径】填写： / 【启动命令】可填写： bash /data/run_train.sh 示例三：代码以压缩包形式存放在云盘中 如果代码文件是压缩包，需要在【云盘路径】中填写 压缩包所在的文件夹路径 ，不要填写压缩包文件本身的路径。 例如，代码压缩包在云盘中的位置为： /project/Offline-task-test-cases.zip 则【云盘路径】应填写： /project 不要填写： /project/Offline-task-test-cases.zip 任务启动时，系统会自动将压缩包解压到与压缩包同级的目录下。假设解压后的训练脚本路径为： /project/Offline-task-test-cases/LlamaFactory/platform/run_train.sh 则【启动命令】可填写： bash /data/project/Offline-task-test-cases/LlamaFactory/platform/run_train.sh 使用云盘代码时请注意： · 【云盘路径】只填写代码所在的文件夹路径。 · 如果代码是压缩包，请填写压缩包所在的文件夹路径。 · 系统会自动将压缩包解压到与压缩包同级的目录下。 · 【启动命令】需要按照解压后的代码目录填写。 如果训练前需要安装依赖，可在【启动命令】中先执行依赖安装命令，再启动训练脚本。 填写启动命令 ​ 在【启动命令】中填写任务启动后需要执行的命令，最多 500 个字符。命令会在当前代码来源对应的工作目录中执行。 选择资源配置 ​ 在资源列表中选择一项资源规格。列表会展示资源名称、GPU / NPU 数量、CPU、内存和显存，支持 CPU、Nvidia GPU、Ascend NPU 等不同类型的资源；不同规格对应的算力点单价不同。 选择镜像 ​ 镜像为必填项，可选择【官方镜像】或【我的镜像】，再从下拉列表中选择具体镜像。官方镜像会标明框架及 Python 版本；【我的镜像】中显示用户已构建成功的自定义镜像。 挂载数据集 ​ 训练数据集和验证数据集均为选填项。点击对应区域的【添加】，在【数据集挂载】窗口中选择需要使用的数据集。 数据集挂载窗口支持以下操作： ·
